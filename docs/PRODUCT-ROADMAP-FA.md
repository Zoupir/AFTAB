# AFTAB 1.0 | نقشه راه مصوب بازطراحی
تاریخ مبنا: 2026-10-26
وضعیت: سند محصول و معیار پذیرش؛ نه نسخه آماده نصب

## تعریف محصول
AFTAB یک لایه orchestration روی موتورهای استاندارد Xray-core و sing-box است، نه پروتکل رمزنگاری اختراعی و نه پوسته‌ای دیگر برای SSH. ارزش محصول: نصب و مدیریت ساده، چندپروفایلی/چندنودی، مشاهده و تشخیص خرابی اتصال در شبکه‌های واقعی و تغییر ایمن و قابل بازگشت تنظیمات.

### مرزهای فنی و صداقت محصول
- هیچ پروتکلی کاملاً غیرقابل‌شناسایی یا غیرقابل‌مسدودشدن نیست؛ احتمال/درصد موفقیت در همراه اول، ایرانسل یا رایتل فقط با تست واقعی قابل‌گزارش است.
- لینک‌های VLESS/اشتراک مرسوم، قابلیت urltest/fallback را به‌صورت خودکار در همه برنامه‌ها اعمال نمی‌کنند. برای sing-box خروجی JSON مستقل با outbound group تولید می‌شود؛ سایر کلاینت‌ها با توجه به توانایی واقعی‌شان لینک/پیکربندی دریافت می‌کنند.
- REALITY مستقیم به سرویس/target درست و سازگار نیاز دارد. SNI، پورت و shortId نمی‌توانند کورکورانه و تصادفی عوض شوند و اتصال را تضمین کنند. REALITY و CDN/TLS مسیرهای مستقل با قیود متفاوت هستند.
- تشخیص ASN از IP درخواست اشتراک احتمالی است؛ کاربر ممکن است از VPN/پراکسی درخواست بدهد. انتخاب دستی اپراتور و آزمون کلاینت مقدم‌اند.
- «محدودیت یک دستگاه» به‌معنی تخصیص هویت مستقل و لغو جداگانه است؛ شمارش IP، سخت‌افزار/HWID یا تعداد اتصال، اثبات انحصار دستگاه نیست و نباید به‌عنوان محدودیت قطعی فروخته شود.
- عدم ثبت مقاصد و محتوای ترافیک پیش‌فرض است. آمار حجمی کمینه و ثبت رویدادهای مدیریتی با چرخه نگهداری محدود خواهد بود.
- برای سایت‌ها و سرویس‌های داخلی ایران، bypass/direct باید به‌صورت قانون سمت کلاینت اعمال شود؛ direct در سرور خارجی الزاماً مسیریابی داخلی ایران نیست.
- چرخش خودکار به IP دوم تنها زمانی مجاز است که IP/نود/دامنه از قبل تهیه و سلامت آن تایید شده باشد؛ تعویض بدون گزینه برگشت ممکن است سرویس را قطع کند.

## معماری مرجع
- `aftab-panel`: Go REST API + React/Vite embedded SPA + SQLite (Postgres optional). صرفاً مدیریت کاربران/نودها/سهمیه/اشتراک/رویدادها.
- `aftab-agent`: یک Agent کم‌اختیار روی هر نود؛ gRPC+mTLS به پنل، API داخلی Xray روی loopback. نصب/تغییر config با اعتبارسنجی، staged apply و rollback.
- `aftab-cli`: نصب، dry-run، وضعیت، آپدیت، بکاپ، restore و حذف ایمن با تایید صریح.
- `aftab-subscription`: مسیر HTTPS مستقل و قابل دسترسی از اپراتور هدف، توکن انحصاری هر دستگاه، خروجی native VLESS URI و sing-box JSON و QR؛ انتشار کلیدها و توکن‌ها به گزارش‌ها ممنوع.
- `aftab-labs`: تستگر opt-in برای همراه اول/ایرانسل/رایتل روی شبکه واقعی؛ بدون گزارش محتوای خصوصی، با برچسب اپراتور و timestamp.

## فازهای تحویل و معیارهای پذیرش

### فاز ۰: گیت معماری و رقابت
- بررسی مستندات رسمی Xray API، sing-box outbound URLTest/Selector، 3x-ui، Marzban، Hiddify، Remnawave.
- Threat model: passive DPI، probing فعال، مسدودسازی IP/ASN، لو رفتن توکن اشتراک، سرقت اطلاعات ادمین، قطع DNS/IPv6، قطع دسترسی به پنل.
- ماتریس feature-gap پروژه؛ ADR برای جداسازی Control Plane و Data Plane.
- تمام تغییرات در شاخه مستقل؛ VPS زنده بدون تغییر.

### فاز ۱: محصول قابل اتصال برای ویندوز و اندروید
- Go backend و SQLite migration با تست.
- نود آزمایشی Xray **مستقل از 3x-ui فعلی** با یک inbound صحیح VLESS+REALITY+Vision؛ انتخاب پورت بعد از بررسی اشغال و یکپارچگی سیستم.
- افزودن، غیرفعال‌کردن و تمدید حساب بدون ری‌استارت هسته از طریق Xray HandlerService؛ جمع‌آوری میزان مصرف از StatsService.
- یک حساب مستقل برای هر دستگاه، سهمیه و انقضا، لینک VLESS + QR، اشتراک HTTPS و راهنمای واردکردن در برنامه‌های Windows/Android.
- بسته نصب dry-run، snapshot/rollback، checksums، تست Go و smoke test دانلود اشتراک؛ هیچ دستی‌کاری دستی در JSON.
- `Definition of done`: ساخت حساب از GUI/API، واردکردن لینک در ویندوز و اندروید، اتصال اینترنت، اعمال حجم/انقضا، قطع حساب بدون restart، snapshot restore موفق و عدم تغییر 3x-ui. بدون این تست‌ها عنوان «نسخه قابل استفاده» مجاز نیست.

### فاز ۲: پنل کاربردی
- React RTL فارسی + انگلیسی؛ UX ساخت کاربر کمتر از ۴ عمل اصلی.
- کاربران انبوه، نودها، آمار، غیرفعال‌سازی، لینک مستقل دستگاه، نقش ادمین و نماینده، 2FA، audit، backup رمزگذاری‌شده.
- آزمون UX واقعی روی مرورگر و موبایل.

### فاز ۳: سازگاری شبکه و fallback
- مسیر اصلی TCP REALITY و مسیر دیگر با TLS+WS/XHTTP و CDN هنگام وجود دامنه و زیرساخت سازگار؛ UDP Hysteria2/TUIC صرفاً fallback آزمایش‌شده.
- خروجی sing-box JSON شامل urltest/selector برای نسخه‌های سازگار، URI مجزا برای کلاینت‌های فاقد گروه.
- تست اپراتور روی سیم‌کارت‌های واقعی و گزارش موفقیت هر مسیر؛ عدم ادعای «روی همه اپراتورها» بدون شواهد.

### فاز ۴: چندنودی و تعویض امن
- mTLS و شناسه مستقل agent؛ health probes از چند vantage point.
- Safe rotation: prepare -> canary -> publish subscription -> observe -> promote/rollback.
- اختلال کامل یک نود نباید پنل و همه اشتراک‌ها را از دسترس خارج کند.

### فاز ۵: امنیت و پایدارسازی
- Code review، تست نشت DNS/IPv6 و kill-switch در کلاینت سازگار، تحلیل آسیب‌پذیری، reproducible builds، نسخه‌های pin شده، امضای artifacts.
- Default deny در مدیریت؛ scope توکن‌ها؛ هیچ مسیر پنل public به‌صورت پیش‌فرض.
- Release gate 1.0 با لیست آزمون واقعی شبکه‌ها.

### فاز ۶: مستندات و توسعه
- راهنما و troubleshooting فارسی/انگلیسی، onboarding مشتری، API/SDK، اپ اختصاصی در صورت اثبات ضرورت.

## قواعد کار با سرور فعلی
- VPS `69.169.109.229` دارای 3x-ui/Xray و AFTAB v0.4 است؛ این‌ها سرویس‌های کاری هستند و نباید ضمن ساخت نمونه جدید تغییر کنند.
- ابزار نصب هرگز `ufw reset`، پاک‌کردن nftables/iptables، اشغال کورکورانه 443 یا تغییر system routes انجام نمی‌دهد.
- در حالت dry-run بدون دسترسی root، تضادهای پورت/سرویس، ابزارها و ظرفیت VPS نمایش داده می‌شود. هر mutation شبکه‌ای پس از snapshot و تأیید انجام شود.
- کلیدهای AmneziaWG آزمایش قبلی که در گفتگو افشا شده‌اند در صورت احیای آن تونل باید تعویض شوند؛ هرگز داخل GitHub، سند یا issue وارد نشوند.
- پایان کار بر اساس خروجی‌های پایدار است، نه ده‌ها کپی‌کردن فرمان SSH توسط کاربر.

## وضعیت واقعی در لحظه ایجاد سند
- AFTAB v0.4: ابزار پراکسی TCP ویندوز، SSH bridge و پنل کاربری اولیه؛ قابلیت استفاده اندروید، VPN سراسری و اشتراک چندپروتکله در آن وجود ندارد.
- ماژول AmneziaWG 3.1 روی VPS آزمایش شد، ولی روی همه اپراتورها قابل اتکا نبود و بخشی از نقشه راه پایه نیست.
- پروژه جدید فقط در شاخه `next/orchestration-v1` تعریف شده و هیچ سرور جدیدی نصب یا نسخه‌ای انتشار نیافته است.
